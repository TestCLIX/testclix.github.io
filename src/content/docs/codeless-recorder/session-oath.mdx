The OATH action lets your scenario pass a time-based one-time password (TOTP) step. Many services use TOTP as a multi-factor authentication (MFA) method during login - apps like Google Authenticator, Authy, or Microsoft Authenticator generate a short-lived code that the user must enter to prove their identity. The OATH action automates this step so you can monitor MFA-protected login flows without manual intervention.

## How to add an OATH step

The generated code is pasted into whichever input field is currently active on the page. Before adding the OATH step, click on the MFA code input field to make sure it has focus.

<Steps>

1. In the recorder, make sure you are in [Live mode](/codeless-recorder/recorder-modes#live-focused).
2. **Click on the TOTP input field** on the page so it receives focus.
3. In the toolbox, select **Add OATH**. If it is not visible, open **More actions**.
4. Choose the key source:
   - **Text** - enter the Base32-encoded TOTP key directly.
   - **Secret** - select a secret stored in the current project. You can create one from the same picker if needed.
5. Enter or select the TOTP key.
6. Click **Submit**.

</Steps>

The recorder generates a fresh code from the key, types it into the active input field, and adds an Authentication event to the timeline.

## How it works

During monitoring, TestCLIX generates a new TOTP code using the selected key and the current time. Because TOTP codes are time-based and deterministic, this produces a valid code for the current time window without any manual input.

Only the TOTP key source is stored - never the generated code itself. A text key is saved with the recording. A project secret is referenced by its stored secret ID and resolved when the scenario runs. Each run produces a fresh code valid for that moment.

:::caution
When you use the Text source, the TOTP key is stored inside the recording. Prefer a project Secret when the key should be managed centrally and rotated without recording it again.
:::

To change the key used by an existing Authentication event, select it in the [Session Timeline](/codeless-recorder/session-timeline), choose a new Text or Secret value in [Event Preview](/codeless-recorder/event-preview), and click **Save secret**.

## Best used for

- Logging into accounts protected by TOTP two-factor authentication
- Passing MFA challenges during automated monitoring of login flows
- Monitoring admin panels, banking portals, or any service that requires a one-time code at sign-in

## Common errors

| Error | Meaning | What to do |
|-------|---------|------------|
| **Error generating token** | The secret is invalid or incorrectly formatted. | Verify the TOTP secret is a valid Base32-encoded key from your authentication provider. |
| **Secret deleted** | The recorded event references a project secret that no longer exists. | Select another stored secret or enter a valid Text key in Event Preview. |

## Caveats

:::note
Only time-based one-time passwords (TOTP) are supported. Event-based one-time passwords (HOTP) are not available.
:::

- Make sure the target input field is focused before adding the OATH step. The generated code is typed into whichever field currently has focus.
- The system clock on the playback environment must be accurate. TOTP codes are valid only within a short time window (typically 30 seconds), so clock drift can cause codes to be rejected.
- If the application rejects a code that was already used within the same time window, playback may fail. This can happen when a scenario is replayed very quickly after a previous run.
