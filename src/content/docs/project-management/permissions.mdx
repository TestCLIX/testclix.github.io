## Introduction

Permissions in **TestCLIX** are assigned **per project**.

A user can have varying access levels depending on the project.

Each project member has:

- **One primary role**: Owner, Admin, Editor, Viewer, or Accountant
- Optional additional permission - **Billing**

This guide explains:

- What each role can see and do
- How permissions work
- How to check your permissions

To invite teammates or update their permissions, see [Users & Invitations](/project-management/users-and-invitations).

## Quick Access Overview

| I want to...                       | Required role                     |
|------------------------------------|-----------------------------------|
| View tests and results             | Viewer                            |
| Replay sessions in Session Player  | Viewer                            |
| Create or edit tests               | Editor                            |
| Run tests                          | Editor                            |
| Modify tests from Session Player   | Editor                            |
| Manage users                       | Admin                             |
| Configure integrations             | Admin                             |
| Access billing and invoices        | Accountant or **Billing-enabled** |
| Full project control               | Owner                             |

## Project Roles

Each project member has a primary role that defines what they can access and manage in that project.

### Owner

Full access to the project, including workspace, integrations, users, and billing.

**Can:**

- Create, edit, run, and delete tests and directories
- Use **Session Player** to replay and compare test sessions
- Manage users and permissions
- Configure integrations and project settings
- Access billing, invoices, subscriptions, and shop purchases
- Promote other users to **Owner**

**Restrictions:**

- An Owner can change or remove their own Owner role only if there is at least one more Owner in the project

### Admin

Manages the project, users, and integrations.

**Can:**

- Create, edit, run, and delete tests and directories
- Use **Session Player** to replay and compare test sessions
- Invite users and manage permissions
- Configure integrations (Jira, Slack, webhooks, API)
- View integration logs
- Manage project settings

**Cannot:**

- Assign the **Owner** role
- Remove another **Admin** or an **Owner** from the project
- Rename the project (**Owner** only)
- Manage billing unless **Billing** permission is granted

### Editor

Works with tests and scenarios but cannot manage users or project-level settings.

**Can:**

- Create, edit, and delete tests and directories
- Record and modify scenario steps
- Run tests (**Execute**)
- Use **Session Player** to replay and compare test sessions
- Mark test errors as acknowledged

**Cannot:**

- Manage users
- Change settings other than personal

### Viewer

Read-only access to the workspace and project results.

**Can:**

- Browse directories and tests
- View history, statistics, dashboards, and search

**Can also:**

- Replay sessions in **Session Player** (without actions that modify the test)

**Cannot:**

- Create or edit tests
- Run tests
- Manage users
- Change settings other than personal

### Accountant

Billing-focused role without access to the test workspace.

**Can:**

- View invoices
- Manage billing settings
- Manage subscriptions
- Use the shop and purchases

**Cannot:**

- Access the workspace
- View or edit tests
- Manage users



## How Blocked Actions Work

Some features may remain visible even if you do not have permission to use them.

Blocked actions:

- Appear **grayed out**
- Show a **lock icon**
- Cannot be clicked
- Display a tooltip on hover:

> "You don't have permission. Contact your Admin."

<img src={blockedActions.src} alt="Blocked action with permission tooltip" />

Actions remain visible so you know the feature exists and may require a higher role.

If you need additional access, contact your project **Owner** or **Admin**.

## FAQ

<details>
<summary>Why can I see a test but not run it?</summary>

You most likely have the **Viewer** role.

Running tests requires **Editor** or higher.

</details>

<details>
<summary>Why are some actions inside Session Player locked?</summary>

Replaying sessions is available from the **Viewer** role, but actions that modify the test - such as **Combine screens** or **Modify scenario steps** - require **Editor** or higher.

Ask your project **Owner** or **Admin** to change your role.

</details>

<details>
<summary>Why can't I open the Users page?</summary>

Managing users requires **Admin** or **Owner** permissions.

You can still view your own role in:

- **Settings → Project**
- **Users → Project overview** (if visible)

</details>

<details>
<summary>Why can't I see the Shop as an Admin?</summary>

**Billing** is a separate permission.

Ask your project **Owner** to enable **Billing** for your account.

</details>

<details>
<summary>Why can't I assign the Owner role?</summary>

Only an existing **Owner** can promote another user to **Owner**.

</details>

<details>
<summary>Who can change my permissions?</summary>

Your project **Owner** or **Admin**.

If you are **Owner** or **Admin** go to:

**Users → Actions → Edit**

</details>

<details>
<summary>Do permissions apply across all projects?</summary>

No.

Permissions are assigned **per project**, so your role may change after switching projects.

</details>
