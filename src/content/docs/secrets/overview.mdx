## Introduction

**Secrets** are reusable values stored in your **TestCLIX** project, so you can reference
them from tests instead of typing sensitive values in plain text.

A secret is defined once in project settings and then referenced wherever a value is needed -
an [extra header](/secrets/extra-headers), an [Insert secret](/codeless-recorder/insert-secret)
step in the recorder, or an [OATH](/codeless-recorder/session-oath) key.

This is useful when you want to:

- keep API tokens, bot-management values, and login credentials out of test configuration
- reuse the same value across several tests without copying it
- rotate a value in one place instead of editing every test that uses it

This guide explains:

- What a secret is and how it is stored
- What the limits are
- Who can create and change secrets

## How It Works

Secrets are **project-scoped**. They belong to the project you are currently working in,
and they are available to every test and recording in that project.

Each secret has:

- a **Name** - up to 128 characters, used to identify the secret when you pick it
- a **Value** - between 1 and 4096 characters, the actual value that is used at run time

When a test runs, **TestCLIX** resolves the reference to its stored value on the server and uses it
in the request or the recorded step. The value itself is never shown in the portal.

:::caution
The value is **write-only**. Once saved, it cannot be viewed again - not by you, and not by
anyone else in the project. The settings page states this directly:
*"Add a reusable secret whose value is write-only and cannot be viewed after saving."*

If you need to know a value later, keep your own copy somewhere safe. To change a stored
secret, you [replace the value](/secrets/manage-secrets#edit-an-existing-secret) rather than read it.
:::

## What You Can Use Secrets For

| Where                                                    | What it does                                                                                                                                                                                                                       |
|----------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [Extra headers](/secrets/extra-headers)                  | A header value's source can be **Secret** instead of **Text**. Available in Add **Scenario**, Edit **Scenario**, Add **Website Availability**, Edit **Website Availability**,  Add **Website Vitals**, and Edit **Website Vitals**.|
| [Insert secret](/codeless-recorder/insert-secret)        | A recorder action that types the value of a stored secret into the focused field. Stored secrets only - there is no **Text** option.                                                                                               |
| [Authentication (OATH)](/codeless-recorder/session-oath) | The OATH key's source can be **Secret** instead of **Text**.                                                                                                                                                                       |

## Limits

Each project can store **50 secrets**. The **Add a secret** heading on the Secrets tab carries a
counter - for example **Add a secret ( 24 / 50 )** - so you can see how much room is left.

When the project is full, the add controls are unavailable and the following message is shown:

> "Maximum of 50 secrets reached. Delete a secret to add a new one."

To make room, [delete a secret](/secrets/manage-secrets#delete-a-secret) you no longer use.

:::note
Deleting a secret does **not** remove the references to it. Tests that referenced the deleted
secret keep the reference and start reporting an error. See
[Troubleshooting](/secrets/troubleshooting) before deleting.
:::

## Permissions

Viewing the **Secrets** tab and the names of stored secrets requires the **Viewer** role or higher.
Adding, renaming, replacing a value, and deleting all require the **Editor** role or higher.

For a **Viewer**, the controls are shown but locked, following the usual
[blocked action](/project-management/permissions#how-blocked-actions-work) behaviour - grayed out,
with a lock icon and a tooltip. You can still reference existing secrets in tests you are allowed
to edit; you just cannot create or change the secrets themselves.

If you need to add a secret and cannot, ask your project **Owner** or **Admin**.

## FAQ

<details>
<summary>Can I see the value of a secret I saved earlier?</summary>

No.

The value is write-only and is never displayed again after saving. If you no longer know the
value, [replace it](/secrets/manage-secrets#edit-an-existing-secret) with a new one.

</details>

<details>
<summary>Do secrets work across projects?</summary>

Secrets are scoped to a single project. A secret created in one project is available only to
tests and recordings in that project.

</details>

<details>
<summary>What happens to my tests if I delete a secret?</summary>

The references remain and become invalid. Tests that use the deleted secret cannot be saved
until the reference is fixed, and existing tests report a **Deleted secret** warning. See
[Troubleshooting](/secrets/troubleshooting).

</details>

<details>
<summary>Why can't I add a secret?</summary>

Either your role is below **Editor**, or the project has reached the limit of 50 secrets.
Check the counter on the **Add a secret** heading.

</details>
