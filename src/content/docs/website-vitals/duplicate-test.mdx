## Overview

**Duplicate** creates a brand-new [Website Vitals](/website-vitals/overview) test from an existing one, copying its configuration - including your metric thresholds - so you don't have to set it up again. The duplicate is a new, independent test - it starts with a clean run history and never affects the test you copied from.

Duplicating a Website Vitals test is useful when you want to:

- Reuse the same thresholds for a similar page or environment.
- Create a **staging** copy of a **production** vitals test (or the other way around).
- Track the same page's performance from a different [location](/website-vitals/location).
- Adjust schedule, headers, or location without touching the original.

## What Gets Copied

- **The full test configuration** - target URL, [metric thresholds](/website-vitals/metrics), [extra headers](/website-vitals/extra-headers), [location](/website-vitals/location), and schedule.

:::note
Website Vitals does not  **record session**, so only the configuration is duplicated.
:::

## What Is Not Copied

The duplicate is a **new, independent test** and inherits no history from the source:

- No past results, scores, or performance trends.
- No triggered alarms or notification history.

## What You Can Change While Duplicating

Anything you leave untouched is inherited from the source test.

| Setting              | Required? | Notes                                                                 |
|----------------------|-----------|-----------------------------------------------------------------------|
| **Name**             | Yes       | Up to **32 characters**.                                              |
| **Parent directory** | No        | Where the duplicate is placed. Defaults to the source's directory.    |
| **Location**         | No        | Run the duplicate from a different [region](/website-vitals/location).|
| **Schedule**         | No        | Turn scheduled monitoring on or off for the duplicate.                |


## How to Duplicate a Website Vitals Test

<Steps>

1. Find the Website Vitals test you want to copy in your workspace.

2. Open the three-dot menu and choose **Duplicate website vitals**.

3. In the **Duplicate website vitals** dialog, review the **Name**. It is prefilled with a default based on the source - edit it if you want.

   > Default: *"Landing (copy)"* (for a source test named *Landing*)

4. *(Optional)* Adjust **Parent directory**, **Location**, or **Schedule**. Leave the rest to inherit from the source.

5. Click **Duplicate**. TestCLIX creates the new test and opens it, ready to run.
   
   <img src={duplicateVitals.src} alt="Duplicate website vitals configuration"/>

</Steps>

### Validation rules

- The **Name** is prefilled with **_&lt;source name&gt;_ (copy)**. You can keep it or replace it.
- **Name is required** and limited to **32 characters**. If the default name would exceed 32 characters, it is trimmed to fit - shorten it further if you like.
  > *"Name is required."*
  > *"Name must be 32 characters or fewer."*

:::note
Duplicating requires **write access** to the project. If the option is missing or disabled, your role may be read-only - see [Roles & Permissions](/project-management/permissions).
:::

## Error Handling

| What happened                | What you see                                                     | What to do                                                                         |
|------------------------------|------------------------------------------------------------------|------------------------------------------------------------------------------------|
| **Name missing or too long** | *"Name is required."* / *"Name must be 32 characters or fewer."* | Enter a name of 32 characters or fewer.                                            |
| **No write permission**      | The **Duplicate** action is unavailable.                         | Request write access - see [Roles & Permissions](/project-management/permissions). |

## Best Practices

- **Name for context, not just uniqueness.** With only 32 characters, favor short, meaningful names like `Landing - LCP` or `Home (staging)`.
- **Inherit thresholds, override targets.** Duplicating keeps your metric thresholds consistent across pages - usually you only need to change the URL and location.
- **Change location for regional copies.** Performance varies by region; duplicating per location is the cleanest way to compare.

## FAQ

<details>
<summary>Does duplicating affect the original Website Vitals test?</summary>

No. The duplicate is fully independent. Changing or deleting it never affects the source, and vice versa.

</details>

<details>
<summary>Will the duplicate include past scores and trends?</summary>

No. A duplicate starts with a clean history and builds its own results from its first run.

</details>
