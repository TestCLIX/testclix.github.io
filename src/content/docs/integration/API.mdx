## Introduction

The **TestCLIX** API allows you to integrate external systems with your workspace.
Access to the API requires a valid **API Key**.

## Authentication

All API requests must include your API key in the request header:

```http
x-api-key: YOUR_API_KEY
```

#### Example 

```bash
curl https://api.testclix.com/v1/api/status -H "x-api-key: {YOUR_API_KEY}"
```
If the key is missing the API returns:

##### 401 Response

```json
{
  "message": "Unauthorized"
}
```

If the key is invalid the API returns:

##### 403 Response

```json
{
  "message": "User is not authorized to access this resource with an explicit deny in an identity-based policy"
}
```

## API Key Management

The API key is scoped to the **currently selected project**, and managing it requires the **Admin** or **Owner** role - see [Roles & Permissions](/project-management/permissions).

To manage your API key:

<Steps>
    1. Open **Settings** from the left sidebar.

    2. Navigate to **Your API Key**.
</Steps>

The **Your API Key** panel adapts to whether a key already exists:

- **No API Key generated** - shows the message *"No API Key has been generated"* and a **Generate API Key** button.
- **API Key exists** - shows the API URL, the masked API key, and the **Refresh API Key** and **Delete API Key** buttons.

<Tabs>
  <TabItem label="Generate">

    When accessing the API section for the first time, no key is available.

    <Steps>

    1. Click the **Generate API Key** button.

    2. The system automatically creates a unique **API key** for your workspace.

    3. The **API key** and API URL are displayed.

    4. Copy and securely store the **API key**.
      ![Generate API key view](../../../assets/api/generate_api_key.png)
    </Steps>

    :::note
    The **API key** grants access to your workspace data.
    Store it securely and never expose it in public repositories.
    :::
  </TabItem>
  <TabItem label="Refresh">

    If your API key has been compromised or needs to be rotated:

    <Steps>

    1. Click the **Refresh API Key** button.

    2. Confirm the action.

    3. A new **API key** is generated.

    4. Update all external systems using the old key.
      ![Refresh API key view](../../../assets/api/delete_refresh_api_key.png)
    </Steps>

    :::note
    Refreshing the **API key** immediately invalidates the previous key.
    All integrations using the old key will stop working until updated.
    :::
  </TabItem>
  <TabItem label="Delete">

    If you no longer need API access for this project, you can permanently delete the key:

    <Steps>

    1. Click the **Delete API Key** button.

    2. In the confirmation dialog, review the message:
       *"Are you sure you want to delete this API key? After this action, the current API key will no longer work."*

    3. Click **Delete** to confirm.

    4. The **API key** is removed, and the panel returns to the **No API Key generated** state.
      ![Delete API key view](../../../assets/api/delete_refresh_api_key.png)
    </Steps>

    :::caution
    Deleting the **API key** takes effect immediately and cannot be undone.
    All integrations using this key will stop working right away.
    To restore access, generate a new **API key** and update your external systems.
    :::
  </TabItem>
</Tabs>

## Endpoints

Available endpoints.

| Method        | Endpoint                   | Description               |Params          |	Codes        |
|---------------|----------------------------|---------------------------|----------------|--------------|
| `GET`         | `/v1/api/status`           | Get test status       | None           | 200          |
| `GET`         | `/v1/api/status/details`   | Get test details      | None           | 200          |
| `GET`         | `/v1/api/status/{test_id}` | Get test status by ID | test_id(string)| 200, 404     |
| `POST`        | `/v1/api/execute/{test_id}`| Execute test by ID    | test_id(string)| 200, 403, 404|

### Get Test Status

`GET /v1/api/status`

Returns overall test status.

#### Example Request

```bash
curl https://api.testclix.com/v1/api/status -H "x-api-key: {YOUR_API_KEY}"
```

##### 200 Response

```json
{
  "status": "pass"
}
```

### Get Test Details

`GET /v1/api/status/details`

Returns detailed test results.

#### Example Request

```bash
curl https://api.testclix.com/v1/api/status/details -H "x-api-key: {YOUR_API_KEY}"
```

##### 200 Response

```json
{
  "status": "pass",
  "tests": {
    "error": {
      "count": 0,
      "items": []
    }
  }
}
```
### Get Test Status by ID

`GET /v1/api/status/{test_id}`

Returns status of a specific test.

#### Path Parameter

| Name        | Type       | Description  |
|-------------|------------|--------------|
| test_id     | string     | Test ID      |

#### Example Request

```bash
curl https://api.testclix.com/v1/api/status/{test_id} -H "x-api-key: {YOUR_API_KEY"}
```

##### 200 Response

```json
{
  "test_id": "01GDZYY7EMI1&07GD8QUVVINJDI",
  "status": "not recorded"
}
```

##### 404 Response

```json
{
  "message": "Test doesn't exist"
}
```

### Execute Test

`POST /v1/api/execute/{test_id}`

Triggers execution of a **[Website Scenario](/website-scenario/overview)**, **[Website Availability](/website-availability/overview)**, or **[Website Vitals](/website-vitals/overview)** test.
The limit of executions is defined by your Test Execution package.


#### Path Parameter


| Name        | Type       | Description  |
|-------------|------------|--------------|
| test_id     | string     | Test ID      |



#### Example Request

```bash
curl -X POST https://api.testclix.com/v1/api/execute/{test_id} -H "x-api-key: {YOUR_API_KEY"}
```

##### 200 Response

```json
{
  "test_id": "01GDZYY7EMI1&07GD8QUVVINJDI",
  "status": "queued"
}
```

##### 403 Response - Execution Limit Exceeded

```json
{
  "message": "Execution limit exceeded"
}
```

##### 404 Response

```json
{
  "message": "Test doesn't exist"
}
```

#### HTTP Status Code Summary

| Code                                 | Meaning                   | 
|--------------------------------------|---------------------------|
| <Badge text="200" variant="success"/>| Success                   | 
| <Badge text="403" variant="danger"/> | Execution limit exceeded  |
| <Badge text="404" variant="danger"/> | Test doesn't exist        |
